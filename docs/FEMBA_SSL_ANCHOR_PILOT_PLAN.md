# FEMBA 预训练与四锚点校准：配对验证试验计划

状态：2026-09-07 的设计备忘。当前已实现并通过 48 项 GPU smoke、86 项测试及 v27 参考核验，执行说明见 [FEMBA_SSL_ANCHOR_PILOT.md](FEMBA_SSL_ANCHOR_PILOT.md)。旧 v1 训练已暂停，旧产物保留。本文不修改旧协议，也不代表已有准确率提升结果。

## 问题与比较矩阵

检验四锚点校准是否提高预测性能，以及是否扩大预训练相对于随机初始化的收益。不预设预训练必须获胜。

沿用 A1 随机冻结、A2 随机监督训练、A3 预训练冻结、A4 预训练全参数微调；每组增加两个配对条件：

| 条件 | 特征处理 | 可训练头 |
|---|---|---|
| C0 无锚点 | 原始 pooled 特征 z | Linear(525,1,bias=True) |
| C1 四锚点中心校准 | z − c_subject | Linear(525,1,bias=True) |

因此试验为初始化 × encoder 训练状态 × 锚点校准的 2×2×2 设计。四组在每个条件内结构一致；八组共享头初始化、采样顺序、数据和选轮规则，成对共享 encoder 初始化。

第一轮仅测试锚点中心减法。不加入锚点尺度除法、绝对值、额外半径特征、KAN、上下文窗口或 KMeans。它是对 v27 四锚点中心机制的独立检验，不是完整复现 v27。若未来检验尺度校准，应注册独立条件并对 A1–A4 全部实施，不能只给预训练组增加组件。

## 四锚点及模型计算

复用 `data/anchors.py::anchor_indices`：在协议指定的 reference_session 中均匀取八个窗口位置 U1–U8，选取 U3、U4、U5、U6。每个锚点只使用自身五秒窗口，无三窗上下文。缺失合格参考段或不足八个窗口时直接报错，不按预测结果替换锚点。

定义 g_theta(x) = mean_tokens(TemporalEncoder_theta(x))，输出 525 维。四个锚点 a_s,k 使用与任务窗口完全相同、共享权重的 encoder：

```text
c_s = (1/4) Σ_k g_theta(a_s,k)
state:    z = g_theta(x)
severity: z = (1/11) Σ_j g_theta(x_j)
C0: logit = wᵀz + b
C1: logit = wᵀ(z − c_s) + b
prediction = sigmoid(logit) >= 0.5
```

状态任务保留原 U3–U6 排除集合，使 C0/C1 计分样本完全一致；C1 额外使用这些窗口作为基线，不给它们计算分类损失。严重度仍为 subject/task-session 单位，固定均匀十一窗，city 保留路径标签。

C1 的 A1/A3 encoder 始终 eval、无梯度；A2/A4 的任务与锚点两条路径都保留计算图，不 detach 锚点中心。encoder 更新后必须用当前权重重算中心，不复用过期特征。可在同一 batch 内按被试去重编码锚点，禁止跨 optimizer step 复用计算图。冻结条件也先保持在线编码，以简化一致性审计。

第一轮统一保留逐窗归一化和逐被试无标签 EA，避免同步更改预处理。EA 使用被试全体无标签窗口，属于离线 transductive 预处理。

四锚点使用已知的协议静息参考段，是显式的个人基线信息，不能称为完全无参考或完全无任务语义的推理。验证被试只用自己的参考段，测试被试也只用自己的参考段；不得用严重度标签、待预测窗口的状态标签或预测表现选锚点。身份划分保持隔离，不混合不同被试的中心。该设计只适用于部署时能取得同类静息参考段的场景。

## 固定训练预算与选轮修正

所有八组同步采用新规则，不能拿旧 v1 已知测试结果直接充当 C0 对照。

- seed=2001；沿用固定 source-train/source-val 与 outer-test 划分。
- AdamW：head LR=1e-3，A2/A4 encoder LR=1e-5，weight decay=1e-2，clip=1.0；CUDA bfloat16 AMP，pooling/BCE 用 float32。
- 状态 batch=32、严重度 batch=4，按目标样本数计；每个 epoch 完整遍历，四组和 C0/C1 使用配对 shuffle。
- 训练 BCEWithLogitsLoss 的 pos_weight 仅从 source-train 目标样本计数；锚点不计为额外负样本。验证 BCE 不加权，无 label smoothing。
- 取消旧版最少二十 epoch 才能入选的限制。令 N 为每 epoch optimizer step 数，间隔 q=max(1,ceil(N/4)) 步以及每个 epoch 末进行完整 source-val 推理；第一次参数更新后也验证。重复 step 只记录一次。
- 任一验证检查点都可入选。按未加权验证 BCE 最小选择，完全平局取较早 global_step；从最佳检查点起超过或达到 10N 个 optimizer steps 无改善时，在验证点早停。最多 60N 步。
- 保存真实最佳 checkpoint，并记录 best_epoch、best_global_step、best_validation 与 last_validation。不得把后续全 source 重训后的已见被试指标称为独立验证结果。
- epoch 边界保存 optimizer、随机数状态和采样进度以便恢复；恢复策略及可能重做的未完成 epoch 必须留审计记录。
- C1 多编码四个锚点，计算开销必然增加。配对控制的是目标样本暴露次数和最大更新步数，同时报告编码窗口数、实际选定步数、GPU 时间与峰值显存，不宣称等 FLOPs。

## 先做验证集 pilot

首轮只做三数据集 fold_1 的两个任务：8 条件 × 3 数据集 × 2 任务 = 48 个训练验证任务。不是完整五折结论，也不是两步 smoke。

先验收合成测试及真实 GPU smoke，再执行 pilot。pilot 仅在 source-train 更新、source-val 选检查点，不做全 source refit，不读取 outer-test 标签、不生成 outer-test 评分。旧训练保持暂停，不能由计划文件自动恢复。

输出预留独立目录 `outputs/femba_ssl_anchor_v2/pilot/seed_2001/{task}/{C0,C1}/{A1,A2,A3,A4}/{dataset}/fold_1/`。正式实现须使用新的协议/schema，记录 condition、锚点索引及哈希、样本哈希、完整初始化、最佳模型和训练审计；禁止覆盖旧目录或混入 v1 结果。

pilot 同时报告 ACC、BACC、AUROC、验证 BCE、类别比例及多数类 ACC。检查点按 BCE 选择，不按某个测试差值或预训练领先幅度选择。逐数据集和逐任务报告全部条件，再计算数据集等权宏平均。

若后续开展完整配对五折，规模为 8 × 2 × 3 × 5 = 240 个 fold 实验。仅跑带锚点的 120 个实验不足以隔离锚点交互作用。完整阶段的 refit 步数换算规则须在启动前另行锁定；本计划不启动完整矩阵。

## 如何判断是否放大预训练效果

对每个 task/dataset 及每个指标 M 分别计算，差值以百分点报告：

```text
锚点自身收益：      G_i = M(Ai,C1) − M(Ai,C0), i=1..4
冻结预训练收益：    P_f(C) = M(A3,C) − M(A1,C)
可训练预训练收益：  P_t(C) = M(A4,C) − M(A2,C)
冻结交互：          I_f = P_f(C1) − P_f(C0)
可训练交互：        I_t = P_t(C1) − P_t(C0)
微调相对冻结：      F(C) = M(A4,C) − M(A3,C)
```

BACC 为判断交互的主要指标，同时完整展示用户关心的 ACC 和 AUROC，不能在结果出来后改换主指标。I_f>0 或 I_t>0 表示该分支上的预训练优势扩大；但若只是随机组变差，不能写成“预训练模型准确率提高”。有利于后续验证的结果须同时满足相应预训练组 G_3 或 G_4 为正，以及对应交互为正，并检查跨数据集方向是否一致。这些是 pilot 的描述性信号，不是统计显著或可靠泛化的证明。

还需报告 P_f(C1)、P_t(C1) 的绝对符号：负差值即使变得较小也不能称为预训练已经优于随机初始化。不能只报告最有利的数据集或分支。对窗口和 city 路径的相关性不得按独立样本夸大证据；单折单 seed pilot 不提供确定性优势结论。

若八组整体改善但交互接近零，只能支持个人基线有帮助；若 A3/A4 改善且交互为正，才支持进一步检验“锚点有助于利用预训练”。没有改善或出现负交互也作为正式结果保留。

## 实现前后的验收

- 核验 C0/C1 均仅 526 个头参数，encoder 结构及成对初始化一致；锚点处理无可训练模块。
- 核验 U3–U6 选择、参考段和被试匹配，目标样本及 shuffle 在八组一致；状态锚点不得进入目标损失或计分集合。
- 用可手算张量验证状态/严重度均值与中心减法、不同 batch 被试的中心广播；关闭锚点时恢复原始 z。
- 冻结组在父模型 train() 后 encoder 仍 eval，参数与 buffer 不变；可训练组任务和锚点分支均能产生梯度，全部 encoder 参数进入 optimizer 并实际更新。
- 核验权重更新后重算中心、重复被试 batch 去重结果一致、无跨步旧特征、保存重载预测一致。
- 核验第一步与二十 epoch 之前的最优模型可被选中；保存的最佳权重而非最后权重用于验证报告。
- pilot 禁止 outer-test 评分；缺条件、混协议、混锚点索引或混计分样本均不能标记 complete。
- 完整代码测试与原 v27 参考结果核验通过后再报告“实现验证通过”；48 项 pilot 完成后另报实际效果。

## 解释边界

旧版过早过拟合和强制二十 epoch 起选是需要纠正的问题；不能预先认定锚点是低准确率的原因，也不能保证新学习率或锚点能提高性能。

三数据集仍使用同一正式预训练 checkpoint。来源脚本涉及 monifeixing，完整预训练样本 manifest 缺失，重叠风险未排除；EA 和参考静息段假设须在报告中披露。新设计已受到旧测试表现启发，即使 pilot 不查看测试标签，后续同一数据集五折也应标为迭代后的探索性证据；强确认性结论需要未用于设计的外部数据或预留独立验证。四组均为 FEMBA，不据此比较 Mamba 与其他架构。
